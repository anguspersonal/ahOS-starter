# Architecture Decision Records (ADRs)

ADRs capture **why** a structural choice was made — the context, the options
ruled out, and the consequences — so the reasoning survives even after the code
moves on. They are the companion to `docs/` (which records the system as it is
**now**) and to [`CONTRIBUTING.md`](../../CONTRIBUTING.md) (which records how we
work).

## Rules

- **Format:** MADR-lite — Context → Decision drivers → Considered options (incl.
  the ones rejected) → Decision → Consequences → Links. The point is recording
  **what you ruled out and why**. Use [`TEMPLATE.md`](./TEMPLATE.md).
- **File name (integer + slug, permanent):** `ADR[NNN]_Descriptive_Title.md` —
  the **next free integer** on `dev`, zero-padded to three digits, claimed at
  authoring and never renamed. Dates live in the metadata block, never in the
  filename. Mint-at-merge and the `ADR-DRAFT-<slug>.md` dance are **retired**
  ([ADR-039](./ADR039_ADR_Immutability_Metadata_And_Guards.md)): they traded a
  collision risk for citation instability (slug → integer mid-life) plus rename
  churn, and failed anyway (the 024 collision). Collisions are now caught by CI
  — see the guards below — and if two branches genuinely race, the second to
  reach CI renumbers on-branch, before any citation exists.
- **Dates & ordering:** every ADR carries `Created:` (authoring date, stable) and
  `Accepted-on-dev:` (the merge date, or `(pending merge)`). **Canonical order is
  by `Accepted-on-dev`**, not by the integer — the integer is a stable label, not
  a timeline.
- **Status:** starts `Proposed`; becomes `Accepted` **only when merged to `dev`**
  (not on dev = not accepted officially), then `Deprecated` or `Superseded by
  <ref>`.
- **Immutable once Accepted — records, not living documents.** Decision content
  (context, drivers, options, decision, consequences) is frozen; changing the
  decision means a **new ADR**. Only **metadata** is edited in place: the Status
  line, supersession pointers, errata/numbering notes, link/typo fixes. The
  test: *if the edit requires no new decision, it's metadata; if it requires
  one, it's a new ADR.* Why immutable: every issue, PR, and agent routine that
  cites an ADR relies on the citation meaning what it meant when written;
  "Accepted" is a status attached to specific frozen content; and reversal
  reasoning must survive as written argument, not as a prose diff
  ([ADR-020](./ADR020_Open_Contradictions_To_Resolve.md) could only be written
  because the original positions still existed verbatim). See
  [ADR-039](./ADR039_ADR_Immutability_Metadata_And_Guards.md).
- **Same-PR supersession stamp:** a superseding ADR must update its
  predecessor's Status line (`Superseded by <ref>` / `Superseded in part by
  <ref> (<clause>)`) **in the same PR** — a reader landing on any ADR finds
  either a current decision or a pointer to its successor, never a
  silently-stale record.
- **Same-PR current-state sync:** an ADR that changes the system's shape
  (components, boundaries, flows, topology) must update the as-built docs — in
  particular
  [`docs/architecture/architecture.md`](../architecture/architecture.md) — in
  the same PR; a process/meta-only ADR states that explicitly instead. ADRs
  answer *why is it this way*; `docs/` answers *what is it now*. Neither
  restates the other.
- **CI guards (enforced, not recommended):**
  [`pr-guards.yml`](../../.github/workflows/pr-guards.yml) runs both as steps —
  the **ADR number guard** fails a PR that adds an ADR whose integer already
  exists on the base branch; the **ADR link guard** fails a PR whose changed
  files link to an ADR path that doesn't exist in the PR's tree.
  Both cover repo files only — a citation in a GitHub issue body is beyond CI's
  reach, which is why an ADR is authoritative to cite only once it is on `dev`.
- **When to create one:** a significant choice that affects more than one system,
  or a choice with real rejected alternatives (incl. a paid-tool / vendor-tier
  choice and the policy it enables).
- **Index discipline:** adding, removing, or renaming an ADR **must** update the
  table below in the same PR — enforced by the docs-index step in
  [`pr-guards.yml`](../../.github/workflows/pr-guards.yml).
